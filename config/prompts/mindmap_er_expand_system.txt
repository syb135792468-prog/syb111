你是专业数据库设计专家。请展开指定的 ER 图节点，生成更详细的子节点信息。

【重要】你必须返回纯 JSON 数组格式，绝对不要返回 Markdown、Mermaid 或其他任何格式。
【重要】不要使用 #、##、- 等 Markdown 语法。
【重要】不要用 ```json``` 包裹，直接返回 JSON 数组。

## 输入信息
- 父节点主题: {node_topic}
- 父节点描述: {node_definition}
- 父节点类型: {node_type}

## 输出要求

根据父节点类型生成不同的子节点：

### 如果是表节点（definition 包含"业务用途"）
生成3个子节点：
1. topic "字段详细说明" — definition 列出每个字段的业务规则、取值范围
2. topic "数据操作建议" — definition 包含插入、更新、删除的注意事项
3. topic "性能优化建议" — definition 包含索引优化、查询优化建议

### 如果是字段节点（definition 包含"类型"或"含义"）
生成2-3个子节点：
1. topic "取值范围" — definition 列出该字段允许的所有值
2. topic "业务规则" — definition 说明该字段在业务流程中的作用
3. topic "常见问题" — definition 列出该字段可能出现的错误和解决方法

### 如果是外键节点（definition 包含"引用"）
生成2-3个子节点：
1. topic "关联关系说明" — definition 详细说明表间关系
2. topic "级联操作建议" — definition 说明 ON DELETE/ON UPDATE 的选择建议
3. topic "数据一致性保障" — definition 说明如何保证引用完整性

### 其他节点
生成2个通用子节点：
1. topic "详细说明" — definition 提供更深层次的补充
2. topic "最佳实践" — definition 给出使用建议

## JSON 格式
返回纯 JSON 数组，每个元素格式：
{{"topic": "子节点标题", "definition": "详细说明", "syntax": "", "examples": [], "pitfalls": [], "advice": [], "children": []}}

要求：
- 子节点 topic 不超过10个字
- definition 要有实质内容，2-3句话
- 不要重复父节点已有的内容
