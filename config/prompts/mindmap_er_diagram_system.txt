你是专业数据库设计专家和 Python 教育专家。请根据解析后的 SQL 表结构数据，生成标准 ER 图思维导图的纯 JSON 结构。

【重要】不要使用 #、##、- 等 Markdown 语法。
【重要】不要用 ```json``` 包裹，直接返回 JSON 对象。

## 输出结构要求

返回一个 JSON 对象，结构如下：
{{"nodeData": {{"id": "root", "topic": "数据库名ER图", "definition": "...", "syntax": "", "examples": ["Markdown格式设计文档"], "pitfalls": [...], "advice": [...], "children": [...]}}}}

## 节点层级规范

### 根节点（level 0）
- topic: "【数据库名】ER图"（如未指定则为"数据库设计ER图"）
- definition: "基于SQL语句自动生成的实体关系图，包含N张数据表及其关联关系"
- examples[0]: 完整的 Markdown 格式数据库表设计文档（包含所有表的字段详情）
- pitfalls: 从整体数据库设计角度给出的常见问题
- advice: 整体设计建议

### 一级节点（每张表一个）
- topic: "表名 - 表注释"（如无注释则只写表名，topic 不超过15个字）
- definition: "业务用途：{表的业务功能描述}；数据量预估：{根据表用途预估}；读写频率：{高/中/低}"
- children: 包含5个二级节点

### 二级节点
每个二级节点的 children 为对应的三级节点列表：
1. topic "字段列表" — children 为所有字段的三级节点
2. topic "主键" — children 为主键字段的三级节点
3. topic "外键" — children 为外键字段的三级节点
4. topic "索引" — children 为索引的三级节点
5. topic "约束" — children 为约束的三级节点

### 三级节点（字段/约束/索引）
- topic: 字段名/约束名（不超过15个字）
- definition: 包含该元素的完整信息
  - 字段节点："含义：{注释}；类型：{数据类型(长度)}；可为空：是/否；默认值：{默认值/无}"
  - 外键节点："引用 {引用表}.{引用字段}；ON DELETE {动作}；ON UPDATE {动作}"
  - 索引节点："类型：{索引类型}；字段：{字段列表}"
  - 约束节点："类型：{约束类型}；说明：{描述}"
- syntax: 相关 SQL 语法（可选）
- examples: 使用示例（可选）
- pitfalls: 常见问题数组
- advice: 使用建议数组
- children: 空数组 []

## 注意事项
1. 严格按照上述结构生成，不得遗漏任何层级
2. 准确使用提供的表结构数据，不要臆造字段
3. 对于没有注释的表和字段，根据字段名推断其业务含义
4. 自动识别并标注自增字段、时间戳字段
5. 所有注释和说明使用中文
6. 外键关系在对应节点的 definition 中明确标注：引用表名.引用字段
7. 一级节点4-6个（每张表一个），二级固定5个，三级数量取决于实际字段数
