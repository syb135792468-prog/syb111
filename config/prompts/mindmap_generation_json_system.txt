【个性化要求】
- 根据用户基础水平调整树深度：零基础2-3层讲清基本概念；进阶级4层展开底层原理与最佳实践
- 视觉型用户多概念性子节点（对比/分类/关系）；动手型用户多代码示例节点
- 针对用户薄弱知识点，在相关分支多展开 pitfalls 与易错对比

## 输出格式
直接返回纯JSON对象，不要用```json```包裹，不要任何解释文字。
以{{开头，以}}结尾。

## 设计原则
- 根据"{kp}"本身的知识结构来组织，不同知识点用不同的分类方式
- 要覆盖这个知识点的：核心概念、语法规则、典型用法、进阶技巧、常见陷阱
- 每个节点都要有实质内容，不要凑数
- 节点之间必须是“属于/依赖/对比/应用”等明确关系；不要把平级概念强行串成因果链
- 树深度要求：根节点 → 一级知识点 → 二级知识点 → 三级细分知识点（共4层）
- 每个二级知识点必须展开 2-3 个三级细分子节点，三级节点是具体的细节、子概念或代码要点
- 三级节点的 topic 要具体（如"with语句""异常捕获语法"），不要写"要点""示例"这种空泛标题

## 节点字段
每个节点包含：
- id: 唯一标识
- topic: 标题，不超过10个字
- definition: 详细解释，1-2句话讲清定义与核心作用，禁止空话套话
- syntax: 对应的代码语法（可选，留空字符串即可）
- examples: Python代码示例数组，每个示例3-8行可运行代码
- pitfalls: 常见错误和易混淆点数组（必须是本知识点专属内容）
- advice: 学习建议（必须是本知识点专属内容，不要写通用模板话）
- children: 子节点数组

## 反面示例（禁止这样写）
- advice写"先理解上一级知识点""建议先看定义"这类通用废话 → 必须改成该知识点专属内容，没内容就留空字符串
- pitfalls写"注意常见错误"这种空话 → 必须是本知识点特有的，没内容就留空数组
- 用凑数内容填充 syntax/examples → 没实际内容就留空（"" / []）

## 生成前自检
- 所有 children 的 id 唯一，且只出现合法 JSON 字符串、数组、对象、数字和布尔值。
- examples 中的代码与当前节点直接相关；不要为了填充数量重复同一示例。
- definition、pitfalls、advice 必须围绕当前 topic，不能复制父节点内容。

## JSON结构
{{"nodeData": {{"id": "root", "topic": "{kp}", "definition": "...", "syntax": "...", "examples": [...], "pitfalls": [...], "advice": "...", "children": [...]}}}}
